# 온보딩 설문 엔진 (PRD §4.3)

**디자인이 나오면 바로 얹을 수 있도록, 로직과 화면을 분리해 둔 것입니다.**
설문 진행·되묻기 판단·응답 수집은 전부 `survey-engine.js`가 하고, 화면은 그 결과를 그리기만 합니다.

- 상태: `verified` (2026-07-21 · Node 상태머신 테스트 + 브라우저 실동작 확인)
- 관련 화면: 와이어프레임 A-02 / A-03 / A-04
- 관련 결정: D-003 (개인화는 선택형+자유 서술을 LLM이 분석)

---

## 1. "AI가 사람마다 다르게 묻는다"를 어떻게 구현했나

PRD §4.3은 문항 추가를 금지합니다.

> "온보딩 이탈을 막기 위해 문항을 다시 늘리지 않는다 — 추가로 궁금한 것은 **문항이 아니라 되묻기**와 행동 데이터로 얻는다."

그래서 **문항 5개는 고정이고, 개인화는 되묻기(probe)로만** 일어납니다.
같은 문항에 답해도 되묻는 문장은 사람마다 완전히 다릅니다.

| 사용자 답변 (Q4) | 생성된 되묻기 |
|---|---|
| "밤에 짖으면 시끄러울 것 같아요" *(주거: 원룸)* | "원룸이라고 하셨는데, 짖음이 생기면 이웃과의 문제가 먼저 걸리실까요? 어떻게 대응하실지 조금만 더 들려주세요." |
| "일단 혼내야죠" | "혼내는 방법 말고, 왜 그러는지 알아보는 쪽은 어떠세요? 그때 어떻게 하실 것 같은지 궁금해요." |
| "몰라요" | "지금 떠오르는 게 없어도 괜찮아요. 대신 가장 걱정되는 상황 하나만 적어주실래요?" |

되묻기는 **문항당 1회, 총 2회**까지입니다 (와이어프레임 A-03 주석 준수). 전부 건너뛸 수 있습니다.

## 2. 디자인이 오면 바꿀 것 — `demo.html` 하나뿐

화면은 엔진이 주는 **view 4종**만 그리면 됩니다. 이 계약만 지키면 어떤 디자인이든 붙습니다.

```js
var s = SurveyEngine.create({ spec: SPEC, llm: SurveyEngine.httpLLM('/api/survey/probe') });

render(s.view());                      // 지금 그릴 것
s.submit(값).then(render);             // 답 제출 → 다음 view
s.skip().then(render);                 // 되묻기 건너뛰기
s.back();                              // 이전
s.result();                            // 서버로 보낼 payload
```

### view 4종

| type | 화면이 그릴 것 |
|---|---|
| `quant` | `title`, `evidence`(근거 카드), `fields[]`(select), `progress` |
| `free` | `title`, `evidence`, `placeholder`, `hint`, `examples[]`, `required` |
| `probe` | `text`(AI 되묻기 문장), 건너뛰기 버튼 |
| `done` | `payload` — 견종·보호견·참여 추천에 공통으로 쓰임 |

에러는 `view().error`에 문자열로 담겨 옵니다. 화면은 그대로 표시하면 됩니다.

## 3. 파일

| 파일 | 역할 | 디자인 교체 시 |
|---|---|---|
| `survey-engine.js` | 상태머신 + 되묻기 판단. **DOM·프레임워크 의존 없음** | 그대로 |

| `demo.html` | 와이어프레임 CSS로 만든 임시 화면 | **이것만 교체** |

## 4. 운영 전환 — 한 줄

데모는 규칙 기반 `mockLLM`으로 돕니다. 실제 AI로 바꾸려면 어댑터만 갈아끼웁니다.

```js
// 데모 (오프라인, 규칙 기반)
llm: SurveyEngine.mockLLM()

// 운영 (Supabase Edge Function → Claude)
llm: SurveyEngine.httpLLM('/api/survey/probe')
```

**API 키는 클라이언트에 두지 않습니다.** 서버가 `survey-prompts.md`의 프롬프트로 호출합니다.
LLM 호출이 실패하거나 3초를 넘기면 되묻기 없이 그냥 넘어갑니다 — **되묻기는 온보딩을 절대 막지 않습니다.**

---

## 5. 설계상 지킨 것

- **원문을 덮지 않는다.** 되묻기 답변은 `followups[]`에 따로 쌓입니다. `answers.q4`는 사용자가 처음 쓴 문장 그대로입니다.
- **정량 응답을 되묻기 판단에 넘긴다.** 주거 형태·시간·예산이 서술과 충돌하면 그 지점을 되묻습니다 (PRD "자유 서술이 정량 응답과 충돌하면 자유 서술 우선").
- **되묻기는 부가 기능이다.** LLM 없이도(`llm: null`) 설문은 5문항으로 정상 완주합니다.
- **용어**: 프롬프트에 "유기견" 금칙, "보호견" 강제 (부록 A).

## 6. 검증 결과 (2026-07-21)

```
초기 view              quant q1
q1 부분입력 → 에러      "모든 항목을 선택해주세요"
q4 공백 → 에러          "이 문항은 꼭 답변해주세요"
q4 답변 → probe        "원룸이라고 하셨는데, 짖음이 생기면…"   ← 정량 응답과 결합된 개인화
q5 짧은답변 → probe    "조금만 더 구체적으로…"                ← 분량 확보용
건너뛰기 → done
되묻기 총 2회 / 원문 보존 확인 / followups 2건 (skipped 플래그 포함)
```

브라우저 실행도 확인했습니다 — 와이어프레임 CSS 그대로 렌더링되고 되묻기 화면(`aibox`)까지 정상 동작합니다.

**데모 실행**: `python3 -m http.server` 후 `/10-survey-engine/demo.html`
(`file://`로 열면 `fetch`가 차단되어 spec을 못 읽습니다)

## 7. 아직 안 한 것

- 실제 Claude 호출 (서버 엔드포인트 미구현 — `survey-prompts.md`에 명세만 있음)
- `done` 이후의 AI 분석(견종 3개 추천) — 별도 작업
- 이탈 후 복귀 시 저장/복원은 `restore()` 인터페이스만 있고 저장소 연결은 미구현
- Unity WebGL에서 호출할 경우의 브릿지 (현재는 웹 기준)
